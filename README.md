# Домовед — база знаний дома Магистральная, 2

Статический сайт для жителей. Публикуется через GitHub Pages, открывается на любом
телефоне по обычной ссылке — без регистрации и приложений.

корне. Настройки публикации: **Settings → Pages → Deploy from a branch → main → / (root)**.

## Ежемесячный цикл

Раз в месяц, после получения выписки со специального счёта:

1. После полной разноски и сверки календарного месяца взять из проверенной
   месячной сводки **оплаты собственников**, **банковские проценты**, **расходы**
   и **остаток на конец месяца**. Учитываются операции с 1-го по последний день
   этого месяца. Проценты не включаются в оплаты собственников.

   Календарный остаток = остаток на конец предыдущего месяца + оплаты + проценты
   − расходы. При наличии других движений их также нужно учесть и сверить.
   `balanceDate` — последний календарный день отчётного месяца. Все суммы
   публикуются с точностью до копеек; незакрытый месяц не добавляется.

   Источник за 2026 год — отдельный расчётный блок листа «2026»: дата — строка 132,
   оплаты — 133, проценты — 134, расходы — 135, остаток — 136. Проверенные исходные
   данные и строка 93 не изменяются. Остаток строки 93 на дату банковской выписки
   используется для квитанций и может уже включать оплаты начала следующего месяца.
   Поэтому он может отличаться от календарного остатка на сайте.

   Контроль согласованной истории: на 31.10.2026 — 317 515,16 ₽. После добавления
   учтённых 02.11 оплат 2 340,90 ₽ и процентов 1 216,27 ₽ получается 321 072,33 ₽ —
   остаток строки 93 на 02.11.2026. Эти ноябрьские движения приведены только для
   сверки; ноябрь публикуется после закрытия месяца.
2. Добавить новую запись в конец массива `months` в `data.js`:
   ```js
   { period: "2026-07", paid: 0, interest: 0, balance: 0, balanceDate: "2026-07-31" }
   ```
3. Если в этом месяце со счёта оплачивались работы — дописать в ту же запись два
   необязательных поля:
   ```js
   { period: "2026-09", paid: 0, interest: 0, balance: 0, balanceDate: "2026-09-30",
     spent: 340000, spentNote: "ремонт кровли, 1-й подъезд" }
   ```
   Тогда в объявлении появится плашка «ИЗРАСХОДОВАНО НА РАБОТЫ», а под ним на
   странице — кнопка «Подробнее о расходе» с текстом из `spentDetails`. В обычные
   месяцы эти поля просто не пишутся, и объявление выглядит как раньше.
4. Задолженность собственников — поле `debt` в той же записи, строго на конец
   соответствующего календарного месяца:
   ```js
   { period: "2026-07", ..., debt: 433079.71 }
   ```
   Для каждого помещения: входящий остаток + начисления по конец месяца − оплаты
   по конец месяца. Суммируются положительные долги; переплаты других помещений
   их не уменьшают. Промежуточная точность сохраняется, округляется общий итог.
   Банковские проценты и расходы на ремонт в этот показатель не входят.

   Источник — строка 138 листа «2026»: F138 — на 31.12.2025, H138 — январь,
   J138 — февраль и далее по месячным столбцам. За незакрытый месяц долг не публикуется.
   Долг показывается в истории, карточке и объявлении выбранного месяца, если поле
   заполнено. Ноль отображается как ноль; отсутствие данных — прочерк в истории,
   без плашки в карточке и объявлении. Прошлые значения сохраняются на свои даты.
5. Сохранить и закоммитить. Через минуту страница `/vznosy/schet/` показывает новый
   месяц, а предыдущие уходят в таблицу «По месяцам».
6. На странице нажать **«Скачать картинку»** — получится готовое объявление в том же
   виде, что вывешивали раньше. Его можно распечатать для подъезда и отправить в чат
   дома.

Ничего больше править не нужно: заголовок, период и суммы на картинке подставляются
сами.

## Как это будет делать бот

`tools/announcement.py` рисует ровно ту же картинку из командной строки или из кода:

```bash
python3 tools/announcement.py \
  --period 2026-07 --paid 71661.16 --interest 8253.70 \
  --balance 2051123.18 --balance-date 2026-07-31 --out iyul-2026.png

# месяц с расходами
python3 tools/announcement.py --period 2026-09 --paid 68000 --interest 8400 \
  --balance 1850000 --balance-date 2026-09-30 \
  --spent 340000 --spent-note "ремонт кровли, 1-й подъезд" --out sentyabr-2026.png

# месяц с задолженностью
python3 tools/announcement.py --period 2026-07 --paid 53173.63 --interest 8296.20 \
  --balance 2112593.01 --balance-date 2026-07-31 --debt 433079.71 --out iyul-2026.png
```

```python
from announcement import render
render(period="2026-07", paid=..., interest=..., balance=...,
       balance_date="2026-07-31", out="iyul-2026.png")
```

То есть бот спрашивает три числа → рисует объявление → отправляет в чат дома и
дописывает запись в `data.js` (коммитом через GitHub API). Макет объявления описан
дважды: в `tools/announcement.py` для бота и в `assets/announcement.js` для сайта —
**при изменении дизайна правьте оба файла**, иначе картинки разойдутся.

## Заявки на акт сверки: WhatsApp и Telegram

Кнопки заказа стоят в двух местах: в разделе `vznosy/` («Акт сверки оплат») и на
странице спецсчёта `vznosy/schet/` («Акт сверки по вашей квартире»). В разметке
кнопка объявляет только текст заявки, адрес собирает `assets/domoved.js`:

```html
<a class="btn primary" data-wa-text="Здравствуйте! Прошу подготовить акт сверки…" hidden>Заказать в WhatsApp</a>
<a class="btn primary" data-tg-text="Здравствуйте! Прошу подготовить акт сверки…" hidden>Заказать в Telegram</a>
<span class="hintline" data-chat-hint></span>
```

Куда ведут кнопки — задаётся в `data.js`: `contacts.whatsapp` и `contacts.telegram`.
Канал без значения просто не показывается (поэтому `hidden` в разметке стоит заранее —
кнопка появляется, только когда есть куда вести). Если не заполнен ни один, вместо
подписи в `data-chat-hint` появляется напоминание дописать контакт в `data.js`.

Номер WhatsApp записывается как удобно — `+7 913 123-45-67`, `8 913 123 45 67`,
`79131234567`: лишние знаки убираются, ведущая `8` заменяется на `7`, номер из десяти
цифр получает код `7`. Telegram — `@username` или `username`, собачка необязательна.

## Что ещё не заполнено в data.js

Эти поля пока пустые — страницы показывают на их месте прочерк или подсказку:

- `contacts.whatsapp` — номер WhatsApp для заявок на акт сверки; пока не заполнен,
  на страницах показывается только кнопка «Заказать в Telegram»
- `contacts.chairperson`, `contacts.phone` — председатель и телефон для связи
- `account.inn` — ИНН владельца счёта
- `house.city`, `house.totalArea`, `account.tariff` — город, площадь дома, тариф

Получатель, директор, банк и счёт регионального оператора уже внесены — они взяты
из бланков заявлений, проверенных фондом.

## Как добавить новый раздел

1. Создайте папку с понятным именем, например `sobranie/`, и файл `index.html`
   внутри (проще всего скопировать `vznosy/index.html` и заменить содержимое).
2. В `index.html` на главной добавьте вкладку в блок `<nav class="tabs">`:
   ```html
   <a class="tab" href="sobranie/">Общее собрание</a>
   ```
3. При необходимости добавьте карточку-ссылку (`<a class="feature">`) и вопросы в
   блок «Частые вопросы» (`<details>` → `<summary>` вопрос → `<div class="body">` ответ).

Чтобы вывести на странице любое значение из `data.js`, достаточно написать:

```html
<span data-dm="account.number"></span>
<span data-dm="months.0.balance" data-fmt="money"></span>
```

Форматы: `money`, `percent`, `date`, `dateShort`, `area`, `tariff`.

## Индексация и приватность

Поиск закрыт в двух местах: `robots.txt` и тег `<meta name="robots" content="noindex,
nofollow">` в каждой странице. Ссылка работает у всех, кому её отправили, но в выдаче
Яндекса и Google страницы не появляются. Захотите открыть — уберите оба.

## Превью в мессенджерах

За картинку и текст при отправке ссылки отвечают теги `og:title`, `og:description`,
`og:image` в `<head>`. Адреса в них абсолютные — при переезде на другой домен их нужно
поменять. Мессенджеры кэшируют превью; для Telegram кэш сбрасывается ботом
[@WebpageBot](https://t.me/WebpageBot).

## Проверка перед публикацией

Тексты заявлений повторяют бланки РФКР МКД, предоставленные фондом; их исходные
файлы лежат в `vznosy/blanki/`. Памятка по оплате собрана по скриншотам приложения.
Если фонд обновит бланк — замените файл в `blanki/` и поправьте текст на странице.
